# Delve

A self-hosted dungeon map editor that Claude controls directly through an API (REST, WebSocket, MCP) while the user watches the map change live in the browser. The full plan is in `docs/PLAN.md` and is also published at https://claude.ai/artifact/X3Ep7LK6fqbYayHsRckUzd. When they disagree, `docs/PLAN.md` wins and should be kept current.

## This machine

Machine-specific instructions (the container, its ports, sudo rules, secrets and the live data) are in `CLAUDE.local.md` next to this file. It is not in the repository.

## Release contract (don't break it)

- `npm run build` must produce `./release/` with entry `release/main.mjs`. It must be self-contained: the bundled server, any `node_modules` it needs at runtime, and the built web files.
- `main.mjs` reads `PORT`, `HOST`, `DELVE_DATA` (= `/var/lib/delve`) and `DELVE_API_TOKEN` from the environment. It must answer `GET /health` with HTTP 200 and JSON.
- `npm run release` builds, then runs `sudo delve-release`. That copies `release/` to `/opt/delve/releases/<stamp>`, switches the `current` symlink, restarts the service and checks `/health`. If the check fails it restores the previous release on its own. It keeps the newest 5 releases.
- `npm run rollback` goes back one release.
- The service runs with `ProtectSystem=strict` and `ProtectHome=true`. It can write only to `/var/lib/delve`.

## Conventions

- TypeScript strict, ESM, Node 24. Vitest for tests. Keep `core` free of Node and DOM APIs so it runs in both the browser and the server.
- All positions are in **grid squares** (origin top left, y down, steps of 0.5). One square is 5 ft by default. Style sizes are in squares too.
- Every change to a map is an **operation** (`add`, `update`, `move`, `delete`, `batch`). REST, WebSocket, MCP and the editor all use the same ops. One request is one undo step. Use `baseRev` for conflicts.
- Rendering randomness (hatching, rough walls) comes from a seeded RNG (map `seed` + object id), so redraws never shift.
- Own code and artwork only. Nothing is copied from Dungeon Scrawl. Its `.ds` layout is used for import/export only.
- End commit messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` on its own line.

## Dungeon Scrawl `.ds` (for the import/export phase)

A `.ds` file is a ZIP with no compression and one entry, `map`. It holds `{version, state:{document:{nodes}}, data:{geometry:{<id>:{polygons, polylines}}, assets}}`. Polygons are in pixels at **36 px per square** and are stored already merged into one outline (a multipolygon). `fixtures/dungeonscrawl/test-map-4p.ds` is the same dungeon as `fixtures/test-map-4p.delve.json`, shifted by (+9, +2) squares. Its outline is the reference for the phase 1 geometry test.
